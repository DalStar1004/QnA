# 1단계 — 배포 전 로컬 코드 수정 기록

작업일: 2026-09-05 · 근거 문서: [Vultr-배포-계획.md](Vultr-배포-계획.md) 3장
상태: **완료 (로컬 검증까지)** · 아직 서버에 올리지는 않았고, 커밋도 하지 않았습니다.

---

## 1. 무엇을 하려던 작업인가

인터넷 서버에 올렸을 때 **주소창에 IP만 치면 게임이 뜨게** 하기 위한 준비입니다.
서버를 사기 전에 로컬에서 끝내야 할 코드 수정을 모아 처리했습니다.
서버에서 처음 고치기 시작하면 무엇이 원인인지 가려내기가 훨씬 어렵기 때문입니다.

## 2. 고친 파일 한눈에

| 파일 | 무엇을 했나 |
|---|---|
| `server/src/server.js` | `/` 는 혼자 하기, `/multi` 는 멀티플레이로 나눔 + 로컬 실행용 그림 경로 보완 |
| `word_connection_game.html` | 멀티 서버 주소를 "지금 보고 있는 주소"에서 자동으로 뽑도록 변경 (3곳) |
| `server/Dockerfile` | 빌드 컨텍스트를 저장소 루트로 올리고, 혼자 하기 화면·그림을 이미지에 포함 |
| `server/docker-compose.yml` | 컨텍스트 변경 반영 + 바깥 포트를 **80** 으로 |
| `.dockerignore` (새로 만듦) | 빌드에 딸려 갈 필요 없는 것(`tools/node` 106MB, `.git` 52MB 등) 제외 |
| `server/.dockerignore` | 더 이상 쓰이지 않는다는 안내를 맨 위에 추가 |
| `server/public/index.html` | 안내 문구·재시도 링크를 `/multi` 기준으로 수정 |
| `README.md` · `server/README.md` | 주소가 두 개가 된 점, 포트 80, 빌드 컨텍스트 설명 반영 |

## 3. 하나씩 — 무엇을, 왜

### 3.1 화면을 두 주소로 나눴다 — `server/src/server.js`

```js
app.get('/', (req, res) => res.sendFile(SOLO_PATH));                       // 혼자 하기 시작 화면
app.get('/multi', (req, res) => res.sendFile(path.join(PUBLIC_DIR, 'index.html')));  // 멀티플레이

app.use(express.static(PUBLIC_DIR, { index: false }));
```

**왜**: 지금까지 `/` 는 멀티플레이 대기실이었습니다. 주소만 알고 들어온 사람은 방 코드를 받을 데가
없어서 아무것도 할 수 없습니다. 시작 화면이 있는 혼자 하기를 앞에 두면, 들어오자마자 혼자 할 수도
있고 [접속하기] 로 멀티로 갈 수도 있습니다.

**놓치면 안 되는 것 두 가지**

- 이 라우트는 `express.static` 보다 **먼저** 등록해야 합니다. `express.static` 이 `/` 요청에
  `public/index.html`(= 멀티 화면)을 먼저 돌려주기 때문입니다.
- 같은 이유로 static 쪽에 `{ index: false }` 를 줘서 그 기본 동작을 껐습니다.

### 3.2 로컬 실행에서도 `/` 가 되게 했다 — `server/src/server.js`

혼자 하기 게임 파일과 그 화면이 쓰는 그림은 **저장소 루트**에 있습니다(`server/public/` 안이 아닙니다).
원본을 한 벌로 두려고 복사하지 않았기 때문에, 실행 방식에 따라 파일 위치가 달라집니다.

- 도커로 띄우면 → Dockerfile 이 빌드할 때 `public/` 안에 넣어 줍니다.
- `서버 켜기.bat` 로 켜면 → 루트에 그대로 있습니다.

그래서 둘 다 받아 주도록 했습니다.

```js
const ROOT_DIR = path.join(__dirname, '..', '..');
const LOCAL_RUN = !fs.existsSync(path.join(PUBLIC_DIR, SOLO_FILE))
    && fs.existsSync(path.join(ROOT_DIR, SOLO_FILE));
const SOLO_PATH = LOCAL_RUN ? path.join(ROOT_DIR, SOLO_FILE) : path.join(PUBLIC_DIR, SOLO_FILE);
```

로컬 실행일 때만 루트의 `assets/`(아이콘)와 배경 4장을 추가로 꺼내 줍니다.
**루트 폴더를 통째로 열어 주지 않았습니다.** 배경은 이름 4개를 목록으로 못박아 두었고,
아이콘은 `/assets` 경로에만 붙였습니다. 그래서 `CLAUDE.md`·`docs/` 같은 것은 나가지 않습니다
(4장 검증에서 404 확인).

도커 컨테이너 안에서는 `ROOT_DIR` 이 `/` 가 되지만 거기에 게임 파일이 없으므로
`LOCAL_RUN` 이 `false` 가 되고, 루트를 뒤지는 길 자체가 열리지 않습니다.

### 3.3 멀티 서버 주소를 자동으로 뽑게 했다 — `word_connection_game.html`

**(a) 기본값**

```js
const DEFAULT_MULTIPLAYER_URL =
    location.protocol === 'http:' || location.protocol === 'https:'
        ? location.origin + '/multi'
        : 'http://localhost:3000';
```

**왜**: 예전 값은 `http://localhost:3000` 고정이었습니다. 인터넷에 올리면 접속자가 [접속하기] 를
누르는 순간 **자기 PC**를 찌르게 되어 아무도 멀티를 못 합니다. 게임 파일을 두 번 눌러 연 경우
(`file://`)에는 뽑아낼 주소가 없으므로 예전 값을 그대로 씁니다.

**(b) 예전에 저장된 주소 처리** — `getMultiplayerUrl()`

이 부분이 빠지면 **기존 사용자만 조용히 고장 납니다.** 예전에 [접속하기] 를 눌러 본 사람의
브라우저에는 `http://localhost:3000` 처럼 경로 없는 주소가 저장돼 있고, 저장값이 기본값을 이깁니다.
멀티가 `/multi` 로 옮겨 갔으므로 그 주소로 가면 다시 시작 화면이 나옵니다 — 아무리 눌러도
멀티로 못 가는 상태가 됩니다.

```js
try {
    if (new URL(saved).origin === location.origin) return DEFAULT_MULTIPLAYER_URL;
} catch (e) { /* 주소가 아니면 저장값을 그대로 쓴다 */ }
```

저장값이 **지금 보고 있는 서버**를 가리키면 새 주소로 바꿔 줍니다.
다른 PC를 가리키는 주소는 사용자가 일부러 적은 것이므로 건드리지 않습니다.

**(c) 서버 상태 확인 주소** — `probeMultiplayerServer()`

주소가 `http://<IP>/multi` 처럼 경로를 달고 오므로 `target + '/healthz'` 로 이어 붙이면
`/multi/healthz` 가 됩니다. `new URL('/healthz', target)` 로 서버 뿌리를 보도록 다시 조립했습니다.

**(d) '서버 켜는 방법' 안내 숨김** — `chooseMultiplayer()`

이 화면이 서버를 통해 열렸다면 서버는 **이미 켜져 있습니다.** 그 상태에서 "폴더에서 서버 켜기.bat 을
더블클릭하세요" 를 보여 주면, 인터넷 주소로 들어온 사람이 있지도 않은 폴더를 찾게 됩니다.
`http(s)` 로 열렸을 때는 그 안내를 숨기고 설명 문구를 바꿉니다.

### 3.4 도커가 루트 원본을 담도록 했다 — `server/Dockerfile`, `server/docker-compose.yml`

`docker-compose.yml`:

```yaml
    build:
      context: ..                  # 저장소 루트
      dockerfile: server/Dockerfile
    ports:
      - "80:3000"                  # 주소창에 IP만 쳐도 들어오게
```

`Dockerfile` 에 추가된 부분:

```dockerfile
COPY word_connection_game.html ./public/
COPY assets ./public/assets
COPY *.png ./public/
```

**왜 파일을 복사해 두 벌로 두지 않았나**: `server/public/` 에 사본을 만들면 반드시 한쪽만 고치는 날이
옵니다. 원본 한 벌을 루트에 두고, 빌드할 때만 가져오게 했습니다.

**왜 `COPY *.png` 인가**: 배경 그림은 파일명이 한글(`배경1.png`)입니다. Dockerfile 에 한글 이름을
직접 적으면 빌드 환경의 문자 인코딩에 따라 못 찾을 수 있습니다. 이름을 적지 않고 `*.png` 로 받고,
루트의 나머지 png(`아이콘.png`·`우승.png`·`챔피언 뱃지.png` — `assets/` 에 잘라 놓은 것을 쓰므로
이미지에 필요 없습니다)는 `.dockerignore` 에서 빼는 방식으로 처리했습니다.
→ **앞으로 루트에 새 png 를 두면 이미지로 딸려 들어갑니다.** 그럴 때는 `.dockerignore` 에 한 줄 추가하세요.

### 3.5 `.dockerignore` 를 루트에 새로 만들었다

도커는 **빌드 컨텍스트 최상단의** `.dockerignore` 만 읽습니다. 컨텍스트가 루트로 바뀌었으므로
`server/.dockerignore` 는 더 이상 적용되지 않습니다(그 파일 맨 위에 안내를 적어 두었습니다).

이걸 빼먹으면 `tools/node`(106MB)와 `.git`(52MB)이 통째로 빌드에 실려 갑니다.
반대로 **지워서는 안 되는 것**도 파일 안에 적어 두었습니다 — `word_connection_game.html`,
`assets/`, 배경 png, `server/src`, `server/public`, `server/package*.json`.

### 3.6 안내 문구 정리

- `server/public/index.html` — 부팅 실패 화면의 재시도 링크가 `http://localhost:3000`(= 이제 시작 화면)을
  가리키고 있었습니다. `/multi` 로 바꿨고, 다른 서버로 들어온 경우 쓰는 `window.location.origin` 에도
  `/multi` 를 붙였습니다.
- `README.md` — 주소로 들어가면 시작 화면이 먼저 뜬다는 점, 배포 계획 문서 링크 추가.
- `server/README.md` — "주소가 두 개입니다" 표 추가, 도커 접속 주소를 `http://localhost` 로,
  빌드 컨텍스트와 `.dockerignore` 위치 설명 추가.

## 5. 아직 확인하지 못한 것 (중요)

- **도커 빌드는 검증하지 못했습니다.** 이 PC에 도커가 설치돼 있지 않습니다(`docker: command not found`).
  `Dockerfile`·`docker-compose.yml`·`.dockerignore` 변경은 **읽어서 맞춘 것이지 실제로 돌려본 것이 아닙니다.**
  Vultr에서 `docker compose up -d --build` 를 처음 돌릴 때 여기가 제일 먼저 확인할 곳입니다.
  특히 `COPY *.png` 가 배경 4장을 제대로 담았는지 봐야 합니다.

  ```bash
  docker compose exec app ls -la public | head -20   # word_connection_game.html 과 png 4장이 보여야 한다
  ```

- **브라우저에서 실제로 클릭해 보지는 않았습니다.** 응답 코드와 구문 검사까지만 했습니다.
  시작 화면 → [접속하기] → 방 만들기까지는 사람이 한 번 눌러 봐야 합니다.

## 6. 이 변경으로 달라지는 점 (쓰던 사람 기준)

- `http://localhost:3000` 이 이제 **시작 화면**입니다. 멀티는 `http://localhost:3000/multi` 입니다.
  `서버 켜기.bat` 은 그대로 쓰면 되고, 열린 화면에서 [접속하기] 를 한 번 더 누르면 됩니다.
- 도커로 띄우면 접속 주소가 `http://localhost` 입니다(포트 80). 예전처럼 3000을 쓰려면
  `docker-compose.yml` 의 `ports` 를 `"3000:3000"` 으로 바꾸세요.
- 예전에 저장해 둔 멀티 서버 주소는 3.3(b) 처리로 자동으로 맞춰집니다. 따로 지울 필요 없습니다.
